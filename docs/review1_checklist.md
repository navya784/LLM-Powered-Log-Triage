# Review 1 checklist: Member 1, Log Intelligence & Data

Goal: convert raw logs into structured events and meaningful semantic groups.
**Must show:** one dataset processed from raw log lines to structured events and semantic groups.
**Do not claim:** that good semantic clustering proves the system can identify root causes.

Status below is what is in the repository, with where to verify it. Numbers and examples are in `docs/review1_report.md`, generated by `python scripts/review1_report.py`.

## Before presenting

1. `python scripts/fetch_loghub.py` then `python scripts/review1_report.py` (default configuration, real sentence-transformers model). The report shipped in the repository may have been generated with the TF-IDF baseline; its first line says which backend was used. Confirm the reproducibility claim for the real model too: run the pipeline twice and compare the three artifacts.
2. `python -m pytest -q` should pass.

## What to say, and not say

- Say: one real dataset, 2,000 raw lines, all parsed, turned into validated events and semantic groups; every step configured, seeded, saved to files, and every group traceable to exact raw lines; grouping quality measured against LogHub's template labels.
- Say: template embeddings group HDFS_2k almost perfectly (ARI close to 1), message embeddings do not (ARI about 0.5 with the TF-IDF baseline): which text is embedded matters.
- **Do not say** the system identifies root causes, or that good grouping implies it can. HDFS_2k has no root-cause labels.
- **Do not say** the method is validated in general. This dataset is easy (14 near-deterministic event types, one service, no hosts, INFO/WARN only), so it cannot separate good methods from mediocre ones. Harder datasets are needed before comparing methods.
- Be upfront about known limits (`docs/dataset_card.md`): no timezone in the data (UTC assumed), the minus sign of negative block ids splits templates, and `service` is `hdfs` for every line by dataset configuration.
